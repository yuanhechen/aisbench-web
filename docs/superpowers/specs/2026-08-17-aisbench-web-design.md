# AISBench Web 可视化插件设计

日期：2026-08-17  
状态：待用户审核

## 1. 目标

为已经安装 AISBench 的 Python 或 Conda 环境提供一个可选 Web 插件。用户只需在同一环境中执行：

```bash
pip install aisbench-web
aisbench-web
```

命令启动内置 Web 服务并打印访问地址。用户打开网页后可以注册、登录、配置个人模型 API、选择共享数据集、创建精度或性能评测任务、查看队列与实时日志，并分析或比较自己的历史结果。

第一版面向一台服务器上的小团队。所有 Web 用户平权；用户之间隔离模型端点、任务、日志和结果，共享服务器上的数据集与执行队列。

## 2. 成功标准

第一版满足以下条件即视为可用：

1. 在已经可以运行 `ais_bench` 的环境中，能够通过一个 `pip install` 安装插件。
2. 执行 `aisbench-web` 后，无需 Node.js、Docker、MySQL、PostgreSQL 或 Redis 即可打开网页。
3. 两名用户可以分别注册、维护自己的模型端点，并且无法查看彼此的端点、任务、日志和结果。
4. 用户可以通过表单提交至少一个精度评测和一个性能评测；任务进入共享 FIFO 队列并由 AISBench 执行。
5. 用户可以实时查看自己的任务状态和增量日志，可以停止自己的运行中任务。
6. 任务完成后能够展示精度摘要或主要性能指标，并能比较兼容的历史任务。
7. 服务重启后，用户、端点、排队任务和历史结果仍然存在；异常中断的运行中任务会被标记为中断。

## 3. 明确不在第一版范围内

- 不修改 AISBench 源码，也不覆盖官方 `ais_bench` 命令。
- 不启动或停止 vLLM、MindIE 等模型服务；模型 API 由用户在外部部署。
- 不支持本地 Hugging Face 模型加载。
- 不提供管理员、角色、审批、邀请或团队管理。
- 不允许用户查看其他人的任务内容或结果。
- 不支持用户上传自定义数据集。
- 不在网页提供共享数据集删除功能。
- 不支持多服务器或分布式调度。
- 不承诺第一版覆盖文生图、视频生成、Agent 等 AISBench 扩展场景。
- 不提供公网生产环境所需的内置 HTTPS、单点登录或企业目录集成。

## 4. 安装与启动

### 4.1 Python 包

发布包名为 `aisbench-web`，Python 导入包名为 `aisbench_web`。包内包含：

- FastAPI 后端；
- 构建完成的 React 静态文件；
- SQLite 迁移脚本；
- 内置数据集目录清单；
- `aisbench-web` console script。

目标服务器不需要安装 Node.js。前端只在开发和构建发布包时需要 Node.js。

插件不把 `ais_bench_benchmark` 声明为会触发自动安装或升级的强制依赖，避免 `pip` 改动用户已经验证可用的 AISBench 环境。启动时通过命令与版本检查给出兼容性提示；发布说明列出已经验证的 AISBench 版本范围。

### 4.2 启动命令

默认启动：

```bash
aisbench-web
```

等价于：

```bash
aisbench-web --host 0.0.0.0 --port 8000
```

可选参数：

- `--host`：监听地址，默认 `0.0.0.0`，方便内网或 VPN 中其他机器访问；
- `--port`：监听端口，默认 `8000`；
- `--data-dir`：数据目录，默认 `~/.aisbench-web`；
- `--max-concurrent-jobs`：最大并发任务数，默认 `1`。

启动流程：

1. 在 `PATH` 中查找 `ais_bench`；
2. 执行轻量自检，确认命令可用且属于当前 Python 环境；
3. 创建数据目录、随机密钥和 SQLite 文件；
4. 执行数据库迁移；
5. 恢复排队任务并处理上次异常中断的任务；
6. 启动 FastAPI、静态文件服务和任务 Worker；
7. 打印本机与可访问的网络地址。

如果找不到 `ais_bench`，服务不会启动，并明确提示用户先在当前环境安装和验证 AISBench。

当监听地址不是回环地址时，启动日志明确提示该服务应仅暴露在可信内网或 VPN 中；第一版不把内置 HTTP 服务描述为可直接暴露到公网的生产部署。

## 5. 技术架构

插件在一个 Python 进程中包含三个主要部分：

### 5.1 Web API

FastAPI 提供认证、模型端点、数据集、任务、日志和结果接口，并托管构建完成的 React 单页应用。

### 5.2 任务队列与 Worker

进程内 Worker 定期从 SQLite 领取排队任务。最大并发数默认是 1，确保不同用户的性能评测不会互相干扰。领取任务使用数据库事务，避免同一任务被重复执行。

Worker 不在当前进程中直接调用 AISBench 内部 Python API，而是使用当前环境中的官方 `ais_bench` 命令启动独立进程组。这样可以保持 CLI 行为一致，也便于停止任务和隔离崩溃。

启动子进程时禁止 `shell=True`。模型、数据集和其他参数必须经过允许列表校验，再由参数数组传递给 `subprocess.Popen`。

### 5.3 数据与文件

默认数据目录：

```text
~/.aisbench-web/
├── aisbench-web.db
├── secret.key
├── jobs/
│   └── <job-id>/
│       ├── generated_config.py
│       ├── process.log
│       └── outputs/
└── downloads/
```

SQLite 保存结构化元数据；AISBench 原始日志、预测、评分和 HTML 报告保留在任务目录。数据库只保存可查询的摘要和安全的相对路径。

SQLite 使用 WAL 模式、外键约束和短事务。HTTP 请求每次获取独立连接，避免在不同线程共享同一连接。

## 6. 用户与安全模型

### 6.1 平权账号

任何人都可以注册并立即登录。没有管理员角色，所有账号拥有相同功能。

账号字段包含唯一用户名、密码哈希、创建时间和最后登录时间。密码使用 Argon2id 哈希，数据库中不保存明文密码。

### 6.2 会话

登录成功后设置随机、不可预测的 HttpOnly 会话 Cookie：

- `HttpOnly`；
- `SameSite=Lax`；
- HTTPS 部署时支持 `Secure`；
- 会话令牌只以哈希形式保存在数据库；
- 服务对改变状态的请求校验 `Origin`。

### 6.3 所有权

以下数据包含 `owner_id`，所有查询和修改都必须同时过滤当前用户：

- 模型端点；
- 评测任务；
- 任务日志；
- 结果摘要；
- 结果对比集合。

仅知道对象 ID 不能绕过所有权检查。文件下载接口通过数据库解析任务目录，不接受客户端提交任意文件路径。

### 6.4 模型 API 密钥

模型端点归创建者私有。API 密钥使用由 `secret.key` 派生的 Fernet 密钥加密后保存；创建后不再完整返回浏览器。`secret.key` 权限设置为 `0600`。

## 7. 共享资源

### 7.1 模型端点

模型端点不共享。每个用户可以创建、测试、编辑和停用自己的 OpenAI 兼容 API 端点。第一版字段包括：

- 显示名称；
- Base URL；
- 模型名；
- 可选 API Key；
- 请求超时；
- 默认最大输出长度。

保存前提供连通性测试，但不能仅因暂时不可达而禁止用户保存。

### 7.2 数据集

数据集全员共享。页面展示：

- 数据集名称和简介；
- 对应 AISBench 配置 ID；
- 未安装、下载中、可用或安装失败状态；
- 预计大小和本地路径；
- 一键安装按钮。

数据集目录由随包发布的清单驱动。下载时使用数据库全局锁和临时文件；同一数据集同时只能有一个安装任务。安装完成前不暴露不完整目录。支持校验和时必须验证校验和。

第一版清单优先覆盖精度和性能流程需要的常用数据集，并同时扫描当前 AISBench 环境中已经存在的数据集。未进入清单的数据集可显示为“已检测”，但不保证支持一键安装。

网页不提供删除共享数据集的功能。

### 7.3 共享队列

所有任务进入同一 FIFO 队列。用户可以看到：

- 自己的任务状态；
- 自己任务的队列位置；
- 前方任务数量；
- 系统当前是否有执行槽。

用户看不到其他人的任务名称、模型、数据集、日志或结果。

## 8. 页面与主要流程

界面采用已经确认的 Codex 风格：冷中性灰侧栏、白色工作区、克制的边框和状态色、单一内容焦点。中英文可切换，默认中文。

### 8.1 注册与登录

注册只要求用户名和密码。用户名唯一，密码最少 8 个字符。注册成功后直接进入应用。

### 8.2 应用导航

左侧主导航包含：

- 新建评测；
- 我的任务；
- 对比分析；
- 我的模型；
- 共享数据集。

侧栏下方显示当前用户最近的任务。没有团队管理和系统管理入口。

### 8.3 新建评测

使用分步表单：

1. 选择自己的模型端点；
2. 选择精度评测或性能评测；
3. 选择一个共享数据集；
4. 填写该模式必要参数；
5. 查看摘要并提交。

普通用户不编辑 Python 配置。提交时后端生成不可变任务快照和 AISBench Python 配置。

精度评测第一版参数：数据条数限制、最大并行 Worker 数、最大输出长度和是否输出详细评分。

性能评测第一版参数：请求数量、并发数或请求速率、最大输出长度、流式模式和是否生成性能可视化。

### 8.4 我的任务

列表只显示当前用户任务，支持按状态、模式、模型和数据集筛选。任务状态见第 9 节。

### 8.5 任务详情

排队或运行阶段展示：

- 配置快照；
- 队列位置；
- 当前阶段和进度；
- 增量日志；
- 停止按钮。

完成后展示结果摘要、原始输出入口和性能 Plotly HTML。失败或中断时展示明确原因和日志末尾。

### 8.6 对比分析

只能选择当前用户自己的已完成任务。第一版比较规则：

- 精度任务按数据集和指标对齐；
- 性能任务展示吞吐、E2E、TTFT、TPOT 等存在的指标；
- 不兼容的任务可以同时选择，但界面明确标记不可直接比较的字段；
- 不生成团队排行榜。

## 9. 任务生命周期

状态机如下：

```text
draft -> queued -> starting -> running -> succeeded
                              |       -> failed
                              |       -> stopping -> cancelled
                              -> interrupted
```

规则：

- 表单校验通过后直接创建 `queued` 任务；`draft` 只用于前端未提交状态，不写入数据库。
- Worker 领取任务后写入 `starting`，成功获得子进程 PID 后写入 `running`。
- 进程退出码为 0 且结果解析成功时写入 `succeeded`。
- 非零退出码、启动失败或结果解析失败写入 `failed`，并保存结构化错误码和可读消息。
- 用户停止排队任务时直接写入 `cancelled`。
- 用户停止运行中任务时写入 `stopping`，向进程组发送 SIGTERM；超时后发送 SIGKILL，最终写入 `cancelled`。
- Web 服务启动时，数据库中遗留的 `starting`、`running` 或 `stopping` 任务写入 `interrupted`；排队任务继续排队。
- 已终止状态不可再次变化。

## 10. AISBench 集成

### 10.1 配置生成

后端维护小而明确的配置生成器，将表单字段映射到 AISBench 的模型、数据集、Runner 和 Summarizer 配置。生成文件写入任务目录，不修改 AISBench 安装目录中的配置。

模型 API 配置第一版基于服务器现有版本支持的 OpenAI 兼容服务模型类。生成器必须通过集成测试验证输出配置能够被当前 AISBench 版本加载。

### 10.2 命令执行

Worker 使用当前环境的 `ais_bench` 绝对路径执行：

```text
<ais_bench_path> <generated_config.py> --mode <mode> --work-dir <job_output_dir>
```

精度任务使用 `all` 或相应默认流程；性能任务使用 `perf` 或 `perf_viz`。

### 10.3 进度和日志

标准输出与标准错误合并写入 `process.log`。Worker 解析 AISBench 已有进度输出和状态临时文件，在能够识别时更新结构化进度；无法识别时仍保持日志可用，不伪造百分比。

WebSocket 只负责实时通知。断线重连后，客户端通过日志偏移量补取缺失内容，因此刷新页面不会丢日志。

### 10.4 结果解析

解析器按任务模式读取：

- 精度：`summary/*.csv`、`summary/*.md`、`results/`；
- 性能：`performances/` 下的汇总和 details JSONL；
- 可视化：AISBench 生成的 HTML。

解析器不得假设所有数据集具有完全相同的指标。无法识别的列作为扩展指标保留，并允许用户查看原始文件。

## 11. 错误处理与恢复

### 11.1 启动错误

- 端口占用：退出并显示冲突端口与解决方法；
- 数据目录不可写：退出并显示目标路径；
- AISBench 不存在或不可运行：退出并显示验证命令；
- 数据库迁移失败：不启动 Worker，避免使用不一致结构。

### 11.2 模型错误

模型端点页面提供独立测试。任务执行时出现连接失败、超时或鉴权失败，由 AISBench 日志和退出码驱动失败状态；页面显示简化原因并提供完整日志。

### 11.3 数据集错误

- 下载使用 `.part` 临时文件；
- 安装成功后原子重命名；
- 下载失败保留可重试状态；
- 磁盘空间不足时在下载前尽早失败；
- 服务重启后清理过期临时文件和安装锁。

### 11.4 WebSocket 错误

WebSocket 断开不影响任务。客户端指数退避重连，并通过 REST 接口获取权威状态和日志补量。

### 11.5 服务退出

收到 SIGINT 或 SIGTERM 时停止领取新任务，等待短暂宽限期，然后终止仍由当前服务管理的子进程组并把任务标记为 `interrupted`。

## 12. API 边界

主要 API 资源：

- `/api/auth/register`、`/api/auth/login`、`/api/auth/logout`、`/api/me`；
- `/api/models`、`/api/models/{id}/test`；
- `/api/datasets`、`/api/datasets/{id}/install`；
- `/api/jobs`、`/api/jobs/{id}`、`/api/jobs/{id}/cancel`；
- `/api/jobs/{id}/logs?offset=`；
- `/api/jobs/{id}/artifacts/{artifact_id}`；
- `/api/comparisons`；
- `/ws/jobs/{id}`。

所有包含用户私有数据的资源都从认证会话获取 `owner_id`，不接受客户端传入所有者。

## 13. 测试策略

### 13.1 后端单元测试

- 密码哈希、会话和 Origin 校验；
- 所有权过滤与跨用户访问拒绝；
- 模型密钥加密和脱敏；
- 任务状态机的合法与非法转换；
- 配置生成器；
- 精度和性能结果解析器；
- 数据集安装锁与路径安全。

### 13.2 后端集成测试

提供假的 `ais_bench` 可执行程序，模拟：

- 正常日志和成功结果；
- 非零退出；
- 长时间运行和取消；
- 服务重启后的中断恢复；
- 多用户同时提交和 FIFO 顺序。

另提供标记为环境测试的用例，在真实 AISBench 环境中运行最小数据集，验证生成配置与当前版本兼容。

### 13.3 前端测试

- 注册和登录；
- 模型端点创建与测试；
- 精度与性能任务表单校验；
- 任务状态、日志补量和取消；
- 结果展示与任务比较；
- 中文和英文切换；
- 无权限资源返回 404 或 403 时的界面处理。

### 13.4 打包烟雾测试

每次发布构建 wheel 后，在临时 Python 环境中验证：

1. `pip install <wheel>`；
2. `aisbench-web --help`；
3. 使用假的 `ais_bench` 启动服务；
4. `/api/health` 返回正常；
5. 首页静态资源能够加载；
6. wheel 不依赖目标服务器安装 Node.js。
